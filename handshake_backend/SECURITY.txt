TLS mixed adapter status

The protocol source is Lean. FieldDag.compile uses a proved translation
validator; X25519.compiled_compute_correct connects accepted arithmetic DAGs
to the RFC-style ladder spec. Existing Boolean AIG compiler theorems cover
HKDF, AES-GCM, Finished, and the handshake-only declassification gate.
JSON serialization, generic evaluators, MP-SPDZ and public OpenSSL certificate
verification remain unverified boundaries, as requested.

The session.py module composes cryptographic stages using secret registers in
one mixed VM. It is a compiler-side interface: it does NOT yet bind the Lean
interactive controller to a persistent native worker. Public requests and
transcript agreement, durable handle ownership, abort erasure, record-shape
selection and epoch rollover must be implemented before production use.
Do not run HandshakeFixture with real secrets: it is explicitly clear testing.

Mixed protocol: pinned MP-SPDZ malicious Shamir over p=2^255-19 with paired
malicious CCD binary shares, five parties and threshold two. Compile with -X
and explicit -P. Native binary field/security settings need five-party tests.
The current compile smoke test uses the compiler default comparison security
40; it does not establish a 64/128-bit end-to-end statistical security claim.

field_to_wire_bits rejects random integers r>=p before opening c=x-r. Given
acceptance r is uniform Fp and c is independent of x. Checked daBits must be
fresh, unbiased, maliciously consistent across domains and never reused.
Its small-field exhaustive and p25519 boundary tests check functionality,
not these cryptographic assumptions. No generic signed bit decomposition is
used on full-width field values. Arbitrary field bits are checked through
fresh secret-random linear combinations of b*(b-1); false acceptance <=1/p
requires inputs fixed before independent coefficients. Checkpoints and checked
openings depend on the pinned runtime's preprocessing and checking semantics.

Permitted releases: ClientHello public key/random, encrypted records,
authenticated public server handshake/alert metadata, authentication and abort
decisions, and uniformly masked conversion/check values. Never release traffic
keys, scalar, ECDH, identifiers or application plaintext. The handshake gate
zeros authenticated application records BEFORE any controller release.

Static malicious MPC does not imply mobile security. Refresh/erasure must
cover scalar, traffic keys, expanded AES/HMAC state, preprocessing and all
copies. A corrupt identity at a transition counts in both neighboring epochs;
at most two distinct identities per accounted epoch. No operational erasure,
native five-party execution, or WAN throughput claim has been established.

Persistent session integration progress:
NativeSession.h now composes the separately exported native functions and
retains handshake/application keys as native shares. Its private reconstruction
method is called only for public key, gated metadata, Finished decision and
client ciphertext. SessionPolicy rejects wrong order, sequence replay and all

TlsMpc/TlsWorker.lean binds the Lean controller to a public RPC interface with

pass through this binding, including full authentication-request comparison.
This is not a live MPC service yet: transport, collective request/program
agreement, dispatch and operational erasure are still required. Native abort
currently invalidates operations; it does not meet the RPC erasure contract.

Public dispatch/transport progress:

runtime. Request agreement hashes the canonical opcode/sequence/length/payload

Public ClientHello random uses party-bound commitments then openings and XOR.

abort erasure explicitly fail; there is no successful erasure acknowledgment.
The Lean TlsWorkerPipe binary framing interoperates with a sanitized C++ public

native cryptographic stages. Real service launch and external TCP remain pending.

Public-length compiler/cache:

Compiler input is ONLY the public wire length. posix_spawn closes inherited
player sockets, RPC pipes and other file descriptors, and uses a separate
process group with a bounded lifetime. Unix IPC tests exercise descriptor
closure; no MPC socket execution is implied. Compilation uses deterministic
relative paths, -M, checked daBits (-X), Fp25519, and security_parameter128.
Each resulting manifest must contain exactly the requested function closure.

Compiler latency and resource bounds remain operational constraints, especially
for large records. This is not yet a throughput result or full-handshake claim.

Application controller and error cleanup (2026-11-07):
TlsApplicationPolicy has 11 kernel-checked endpoints for reservation, update
ordering, response obligations, aborted-state guards and receive/half-close
state. The public policy uses a conservative 2^24 sending-record budget and
2^48-1 sending-epoch ceiling. It does not impose these sender ceilings on peers.
TlsApplication serializes private backend calls over opaque handles, reserves
before cryptographic effects, sends KeyUpdate with old keys before installing
new keys, and catches both protocol and underlying I/O exceptions. Separate
reader serialization permits a send while public receive I/O waits. Both closed
directions invoke backend cleanup. No durable resume/rollback protection or
formal effectful-controller refinement is claimed.

The native application RPC/method binding now exists but is NOT operational:
actual handshake-state retirement is a mandatory gate and remains unimplemented.
Its openRecord must authenticate, validate and assemble post-handshake messages inside MPC;
only the typed control event may be opened, and application payloads remain
opaque handles. The mock Event producer in ApplicationFixture is test-only and
provides no evidence for that private parser. Native retirement and abort
still explicitly fail because complete VM erasure is not implemented.
The new cleanupOnError wrapper also fixes initial-handshake cleanup on I/O
exceptions and explicitly propagates cleanup failure. Tests cover 305 policy
boundary checks, key-update ordering/crossed requests, 32 concurrent sends,
duplex scheduling, malformed framing, half-close and terminal error paths;
19 OpenSSL initial-handshake fixtures still pass. None executes native MPC.

Native application interface (2026-11-07):
Opcodes12..16 bind open/seal/control/rotate operations. Open returns event2 or
event2+opaqueID8; it never returns private content length or plaintext. The
native buffer registry stores shared data and length. IDs are monotonically
allocated, scoped to one worker, never reused, and bounded to4096live entries.
No buffer drop/reuse or shared Signal/H2 producer is connected yet. The internal
retain_fixed_payload interface accepts same-worker shared circuit outputs only;
it is not a public import or opening RPC. Received buffers have private lengths
and cannot be sealed directly as a fixed-size application payload.

ApplicationPolicy enforces native reservations, exact sequences, record budget,
crossed/requested update rules, send-before-rotate and half-close. Native send
matches the reserved ciphertext. The native parser opens only event/request2;
DEFER reuses the original shared record/state and never commits placeholders.
Kernel descriptors must already be pinned; dynamic application-shape preparation
and full-size control kernels are unfinished. These methods compile/link but
have not run inside MPC. application_ready remains false, retirement throws,
and rotations explicitly refuse to acknowledge unimplemented old-key erasure.

Opcode17 polls one record without blocking the worker. Partial public ciphertext
is buffered with the standard16640-byte body bound, leaving other operations
able to run. Application receive polls with a30-second deadline. Whole pipe
exchanges are mutex-serialized; framing/I/O/rejection failures make the pipe
terminal. All-party request scheduling still needs deployment integration;
local concurrency tests do not establish distributed progress or agreement.

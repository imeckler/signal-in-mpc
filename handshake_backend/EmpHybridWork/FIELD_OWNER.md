# Native field owner checkpoint

`field_engine.{h,cpp}` instantiates MP-SPDZ's documented `ProtocolSetup`/`ProtocolSet` over authenticated `Share<gfp_<17,4>>`, exact p=2^255−19, in a separate translation unit from EMP. Counter17 avoids the existing mixed/no-mixed default-type instantiation collision. No native MAC or share is cast into EMP. Inputs, multiplication and opening use the supported protocol APIs; opened values remain quarantined until `MAC_Check::Check` completes. Local handles bind owner generation and index and contain no share values. One serialized owner is the current profile; concurrent owners/global field initialization are unsupported.

`build_field.py` captures commands and actual compiler dependency hashes against the previously pinned candidate runtime. `check_field.py` creates fresh local TLS certificates/key/preprocessing directories and runs two parties. The first equality verifies two private products; the second consumes the retained authenticated product sum. Only two public fixture equality zeros open. This is a native arithmetic-owner control, **not EMP interoperability or checked-daBit evidence**. All share input values here are public-known disposable test values. The eventual bridge will restrict openings to sacrificed preprocessing/masked values.

The native `CryptoPlayer` path exposed a byte-accounting limitation: the prior raw socket overlay misses OpenSSL BIO payloads. Its small socket numbers are preserved as incomplete diagnostics, not total traffic. `Player.total_comm()` separately reports native protocol bytes, including child channels, excluding TLS framing. No exact full-wire or performance claim follows. This tiny control generates much unused live preprocessing (batch10000); it is not a steady throughput benchmark.

Remaining owner obligations include binding both engines to the same authenticated session/frame, checked daBit generation, canonical range/mod-p conversions, actual tamper/replay tests, cleanup on caught/uncaught failures, wipe of private containers/slack/stack and remote channel identity. The stock runtime can terminate on some errors. Successful control execution does not discharge these obligations or enable a production gate.

# First actual cross-engine coin control

`bridge_coin_fixture.cpp` runs current EMP and native MASCOT in separate implementation translation units within each A/B process. It uses configured ell16/B8/C2 from `parameter-report.json`:256 candidate contributions per party,128 cut positions,128 combined coins in16 buckets of8. Both engines settle inputs before a fresh commitment/open challenge. Sampling uses SHA256 stream/rejection sampling (not modulo-biased shuffle). Each cut opens both parties' selected contributions in both engines and checks exact0/1 equality. Remaining contributions are XOR-combined (native x+y−2xy). A second fresh challenge buckets them. Authenticated XOR differences against each bucket representative must agree in both engines before the16 representatives may be used.

The control consumes these16 pairs for Boolean-bit→field conversion, opening only the masked XOR and final equality predicates. No logical application secret is opened; all input bits are disposable public-known fixture data. Deliberately supplying2 for every corrupt party native contribution rejects at the cut, before accepted pairs/conversion. Both positive parties exit0 and both negative parties exit4; controllers reap all children. These vectors do **not** prove the RW theorem instantiation, all malicious distributions, or backend correctness.

This is a fixed-size local fixture, not an admitted reusable bridge API. A typed verified-pool ownership/consumption ledger, bound remote identities/session/operation frames, cross-session/replay/MAC fault controls, arbitrary field→Boolean conversion, canonical mod-p encoding proof and X25519 integration remain outstanding. The current challenge context is a fixed compiled local-A/B domain plus phase; it is not deployment authentication. The selected construction's security composition with the unaudited EMP implementation remains unmechanized. No production gate changes.

Positive cold wall1.307s includes fresh keys/preprocessing and fixture setup; this is **not** sustained conversion throughput. Native protocol payload153,654,690B/party includes mostly unused batch10000 preprocessing. EMP totals91,269/82,677B sent per party reconcile opposite receives after teardown. Native raw socket counters omit OpenSSL BIO payload and cannot establish full wire totals; native protocol counters exclude TLS framing. Generated/consumed preprocessing normalization and exact encrypted wire accounting remain required before comparison.

Reproduce after pinned builds: `python3 handshake_backend/EmpHybridWork/build_field.py`, `python3 handshake_backend/EmpHybridWork/build_bridge.py`, `python3 handshake_backend/EmpHybridWork/check_bridge.py`. Existing MP-SPDZ and EMP source/security pins and compatibility/counter overlays are inherited from the comparison work; no security guard was removed. All results are loopback/shared-development-host controls, not WAN estimates.

# Boolean backend route: complete the modern EMP engine (candidate v3)

Status 2026-11-09: route recommendation plus an implemented, regression-tested candidate. **Not accepted.** `secure_hybrid_backend` stays `false`; the review items at the end gate acceptance. This addresses REMAINING_WORK.md section 3 step 1 and starts steps 2–3.

## New finding: the input-only repair still leaks garbler wire values

In the pinned engine (`a245ca0…`, also with the `private-input-v2` repair) the evaluator B reports the masked value Λ of every AND output to the garbler A, and A answers with `H(M1_t)`, a digest of A's MACs on its share of each check bit c_γ. A never checks the reported Λ.

If B flips the reported Λ of one AND output that feeds operand 0 of a later AND gate, A's MAC for that later gate shifts by `K_B[r] ⊕ r·Δ_B`, where r is A's share of the mask on operand 1. B holds `K_B[r]` and `Δ_B`, so A's digest is a one-bit oracle for r. With r, B's own share and the public Λ, B learns the **actual value** on that wire. Neither party aborts. k independent flips cost 2^k hashes and yield k wire bits per chunk.

`check_validation.py` reproduces this: in 8/8 runs with a fresh random private bit, B recovers A's private input bit from a chunk whose honest output is constant and never opened; both processes exit 0. This is a finding about this implementation. The route does not depend on whether the published protocol text intends an equivalent check (see sources).

## Routes compared

| | Legacy v0.3.0 (WRK17, `356cfd8…`) | Modern engine + v3 (recommended) |
|---|---|---|
| Garbler learns masked values | No, so this leak class is absent | Yes; needs the label check below |
| Carried authenticated state across calls | None (single circuit per `C2PC`) | Native (`AG2PCSession` carried wires); required for ratchet/TLS state |
| Known defects | 20-bit `MASK` comparisons, print-and-continue mismatches (overlaid in `emp-ag2pc-failclosed`), IKNP malicious check disabled inside `LeakyDeltaOT` | Raw input transmission (v2 repair), unauthenticated PUBLIC/A output, the leak above |
| Online cost per AND | 3κ + 4ρ bits | 2κ + 2 bits (v3 adds one digest per chunk) |
| Hybrid work already built on it | None | Conversions, pools, padding, curve adapter |

Legacy would need a new reactive-state layer written and argued from scratch; the modern engine needs three local, checkable changes. Recommendation: modern engine with v3. Legacy remains the fallback if the v3 review fails.

## v3 changes (generated by `prepare_validation_v3.py` from the hash-pinned v2 tree)

1. **Evaluator masked-value check.** With Λ_AND, B sends `H(L_{γ,Λγ})` over the AND-output labels it holds. A recomputes `H(L_{γ,0} ⊕ Λγ·Δ_A)` and aborts on mismatch **before** releasing `H(M1_t)`. The label is an IT-MAC tag on Λ under Δ_A, so this is an `Open([Λ]_B)`. Once it passes, A's digest is computable by B alone and carries no information; and every Λ that A carries forward is authenticated (inputs are owner-chosen, XOR/NOT are linear, AND outputs are checked).
2. **Directed outputs.** Every opening is an authenticated share `Open` to the recipient, who combines it with its own Λ. PUBLIC is an opening to B then to A; no plaintext is forwarded. Peer bytes are validated before indexing. No fairness: B may hold a PUBLIC value when A aborts.
3. **Check ordering.** The COT consistency check now runs before any dependent message: after mask draws in the input phase, after triple generation and before garbling, and before every opening.

4. **Triple generation.** Function-independent form: every bucket layer is a fresh random triple, checked before it is combined; the bucketing coin is a commit/open joint coin; the merge bits and the Beaver differences that join the gate's masks to the finished triple are authenticated opens. This replaces the stock in-place construction, whose unauthenticated correction bits also undermined change 1. See [TRIPLE_POOL_AUDIT.md](TRIPLE_POOL_AUDIT.md).
5. **Digest tags.** Every check digest is bound to its purpose, sender and a lockstep counter.

Diff: `emp-ag2pc-validated-v3.patch`. Attacker hooks only: `emp-ag2pc-lambda-diagnostic-v2.patch`.

## Protocol mapping and sources

- Base protocol: Katz–Ranellucci–Rosulek–Wang, eprint 2018/578 (CRYPTO 2018). Abstract page read: note "Add a note that version 1 requires a higher roundtrip complexity", last revision 2018-10-11. **The eprint PDF returned 403 and was not read.** The protocol figure used here is the copy in Wang's thesis, Figure 5.2 (`.deps/two-party-comparison/xiao-thesis.txt`): steps 3–4 inputs, 6–8 "P_B sends ẑ_w … use Open to check that c_γ is 0", 9 output to P_B only. That figure gives P_A no output and no check of ẑ; its malicious-P_B proof says only that the simulator acts as an honest P_A.
- Label as MAC on the masked value: Cui–Wang–Yang–Yu, EUROCRYPT 2023 (copy from par.nsf.gov, purl 10567173): "the masked value of each wire is implicitly authenticated by the garbled label", and "(L_{w,0}, L_{w,Λw}, Λ_w) as an authenticated bit [Λ_w]_B, where L_{w,0} is considered as the local key and L_{w,Λw} plays the role of MAC tag". Change 1 applies the standard hashed `Open` to that authenticated bit.
- Dittmer–Ishai–Lu–Ostrovsky, CRYPTO 2022, §2.1 restates KRRW as "B opens all masked wire labels to A, and A then batches together the proof of correct garbling"; no flaw is described there.
- I found no published statement of the leak above. The attack analysis and the v3 composition argument are this work's own and are unreviewed.

Pins are unchanged: AG2PC `a245ca0f…`, emp-tool `339bde84…`, emp-ot `5072bdab…`, SoftSpoken⟨4⟩ malicious, κ=128, configured ρ=40 (not 128).

3. Malformed-encoding and both-role attack coverage beyond the cases above; garbler-side deviations (bad G rows, bad b bits, bad input labels) have only the retained-Δ control.
4. Padding: the executable tiny-kernel control passes on v3 and original-output equivalence is kernel-checked for a Lean model (`PaddingSemantics.lean`). The model is hand-written from `pad_program.h`, not extracted, and not yet joined to the compiler.

## Reusable-cell policy checkpoint

`PrivateReusableOutboxV1` uses four1310-byte cells (presence1, typed payload1293, original private requestID8, generationBE8) plus four dispositions. A public bounded ordinal selects the destination; private eligibility accepts only canonical absent/0 or present255/observed-accepted3. It rejects dispositions1/2/4/5 and malformed cells. All other cells and IDs/wires are preserved exactly, without shifting. This conservative policy may reject a selected occupied cell even if another cell is free; it never discards unresolved entries to obtain space. Ordinary acknowledged sends can reuse cells indefinitely without coupling cell index to global certificate number.

The inserted cell must have actual valid payload/status and match the expected nonzero public certificate generation represented as shared bytes, distinct from the prior cell generation. The embedding owner must bind that expected generation to the actual authorized certificate sequence and bind response leases to cell+generation+head+boot; the circuit alone does not prove global monotonicity or authorize ACKs.

# Narrow trusted indexed Std Zip model

This is a trusted standard-library content/borrow model for the actual U64 slice-iterator pair used by portable AES add_round_key. It is NOT an extracted proof of Rust Zip, generic Iterator, allocator, pointer validity, Drop or erasure. No whole add_round_key/AES output is provided by the model.

The selected pinned source is the indexed specialization: core slice IterMut and Iter both implement TrustedRandomAccess (slice/iter.rs2987–3003); ZipImpl for that pair initializes index0 and len=min remaining, advances only Zip.index, and uses indexed get_unchecked (iter/adapters/zip.rs288–316). Both underlying starting positions remain fixed. This is deliberately different from the generic left-next/right-next fallback.

`StdBorrowZip.lean` models exactly that applicable state: owners and initial positions, adapter index and minimum remaining length, yielded pairs, captured-cell mutable writeback and shared-owner preservation. The constructor continuation restores the complete mutable iterator owner; next's continuation restores the yielded mutable cell into the complete future owner. None performs no write. Invalid descriptors that violate the constructor invariant fail closed; no Rust UB equivalence is claimed outside valid iterator states. `ModelSemantics` proves valid indexed access, exhaustion, owner length/cursors/shared preservation, updated-cell and untouched-cell observations, including arbitrary nonzero origins and unequal remaining lengths.

The owner value and pending borrow continuation together are the observation. Physical Rust memory is updated as each mutable reference is used; this functional model restores those writes through the generated backward continuations. It does not claim equality of a bare forward owner snapshot mid-borrow. The supported AES caller visits strictly increasing distinct indices, never rereads earlier mutable cells, never modifies the shared key owner, and applies the complete continuation before returning. The fixture tests likewise observe yielded pairs/size hints and fully restored owners, including early destruction. Generic revisiting, nth/backward iteration, arbitrary callback misuse, or aliased invalid Rust borrows are outside this model.

The actual assertion, both actual XOR-assignment bodies and actual AES loop are unchanged. `prepare.py` adds ONE import to the unchanged generated Funs, checks an exact inverse, and records hashes. The scoped compatibility trait reflects the mutable-reference callback signature the generated body already requires. All names are confined to RustCryptoAesZipDiagnostic; official models, frozen diagnostic sources, Rust bodies and generated computations are untouched.

`check_proofs.py` replays the existing exact four-unused-dictionary-slot selection with all actual function declarations identical, invokes unchanged pinned Aeneas, byte-compares original Funs/Types and checks the import-only replay. Fourteen kernel endpoints establish model contracts and the complete actual eight-step round-key assertion/XOR/loop result for arbitrary operands, including wrong-key-length assertionFailure. `numeric_words` connects that actual source result to eight concrete 64-bit XORs. This is implementation agreement relative to the stated trusted Std model, not an extracted Zip proof or whole AES equality.

The PUBLIC-only Rust oracle is built with the pinned Rust compiler and locked dependencies. The exact vendor fixslice64.rs prefix is preserved and only forwarding functions are appended in an isolated ignored build directory; the original module is not edited. The source-selected Std files are byte-verified against the pinned Rust source archive. The3260 public differential cases compare actual Rust indexed slice Zip and actual private AES add_round_key against the scoped model/unchanged generated loop: nonzero starting iterator positions, unequal remaining lengths, early destruction and untouched suffixes, repeated None, complete owner writeback, all1024 operand basis bits, random words, and debug-assertion rejection before state changes. The selected fixture profile has debug assertions and64-bit usize; supported production callers always supply eight words. These tests do not establish generic iterator/internal-cursor behavior beyond the stated specialization, memory cleanup, native MPC, throughput or application readiness.

Run `build_oracle.py` once for a new isolated source stage, then `check_model.py` and `check_proofs.py`. Whole inv_bitslice equality, AES round/key/layout composition, actual CTR stream/XOR/buffering, HMAC and higher wrappers remain required work.

# Actual portable AES trait-wrapper frontier

The cryptographic entry and key schedule are already connected to the isolated executable candidate in FixsliceCircuitV1Work. This work extracts the remaining unchanged Rust soft backend/public-trait packaging. No wrapper agreement is claimed yet.

The concrete Harness is only a call root into unchanged pinned aes/cipher crates. Its encrypt_one uses the actual public in-place API; encrypt_four is explicitly four sequential one-block calls, not the parallel backend. No harness encrypts bytes itself. Exact dependency versions/checksums are checked against libsignal's Cargo.lock. Neither existing oracle binaries nor production files are modified.

The direct generic impl root extracts actual method bodies but Charon's post-associated-type-lift root matching loses those roots. Full monomorphization can return success with an empty graph: this is rejected, not accepted as a proof. Module-root extraction retains some concrete functions but omits the lifetime-generic backend. A concrete public call root retains the actual backend. Full monomorphization then fails Aeneas's region-type/borrow sanity checks; naming-only replay does not fix it. Partial mutable-reference monomorphization retains regions, but pinned Charon rejects mismatched lifted BlockCipherEncClosure trait clauses. No sanity check is disabled and erroneous graphs are not translated as accepted references. boundary-report.json preserves exact receipts and diagnostic hashes.

The approved next library boundary is limited to actual fixed16-byte/4×16-byte hybrid-array and InOut content/borrow operations: default-zero batch, identity array conversion, checked index0, clone_in before write, get_in/get_out and complete mutable-owner writeback. It must model both equal pointers (in-place) and nonoverlapping input/output, preserving untouched owners/suffixes and failure behavior. For this actual wrapper, clone_in happens before the only output write; treating that observed read as an entry snapshot is valid only within this restricted caller, not a general aliasing model. Both borrow continuations must remain represented. This is an explicit trusted library-content boundary, not an assumption that AES or its wrapper returns the desired ciphertext. Generic heap/address/unsafe-pointer/Drop and extracted library-implementation proofs remain outside this functional boundary.

Concrete blockers: canonical partial monomorphization's lifted trait mismatch, and representing the fixed InOut owner/borrow abstraction to the translator without erased regions or removal of live computational trait references. The parser's accepted specialized Prost candidate does not repair this graph. Next work must isolate this dispatch/content binding or a narrowly reviewed translator repair, then compose the unchanged actual wrapper with the existing actual key schedule/AES/compiler theorems and the actual CTR generator. Full stream buffering/XOR, HMAC/KDF and sealed-sender source composition remain open.

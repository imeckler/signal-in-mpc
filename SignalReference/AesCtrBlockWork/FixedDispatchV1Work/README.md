# Fixed AES-256 soft-backend dispatch/content binding

This is a source-instantiated reference under an explicit trusted dispatch/library boundary, not a claim that the original generic GAT/InOut graph translated. The rejected original graphs and exact diagnostics remain in BackendWrapperV1Work/996378d. Production sources/artifacts are unchanged.

extract_complete.py checks the pinned soft.rs checksum and copies the literal encrypt_block/encrypt_par_blocks statement text. It instantiates only the macro-selected aes256_encrypt symbol and visibility; the inline attribute between methods is a compiler hint outside the copied statement bodies. The selected/instantiated text and hashes are retained. A tiny fixed library content model supplies native16/4×16 arrays and InOut entry-read/complete-output owners. This avoids generic trait/GAT/pointer internals. Dispatch to the AES-256 soft implementation, this fixed library content abstraction and Rust/Aeneas translation are trusted boundaries.

The actual cryptographic linkage is a Lean DEF forwarding to the unchanged translated Rust aes256_encrypt, whose key schedule, entry, layout, round and compiler agreement are already proved. It is not an assumed AES result. Aeneas-generated wrapper computations are unchanged; both get_out continuations appear in the generated function and remain in the proof. check.py audits ten foundation-only endpoints, including computed32-byte key→single wrapper→compiled16-bit projection. The parallel wrapper is separately connected to the actual four-block encryption entry. All bit values and previous output contents are unrestricted.

InOut's input field means the observed pre-write input content. For this caller clone_in/get_in occurs before its sole output write. For equal pointers the observable output owner is replaced; the stored entry snapshot is not a claim that rereading the physical input pointer after writing would return the old value. For disjoint owners the input owner is untouched. This abstraction is limited to the selected wrapper's read-before-write trace, excludes later arbitrary aliasing observations, and preserves the complete output owner. No unsafe-pointer/address/allocator/Drop/erasure correctness is claimed.

check_library.py executes256 public fixtures/2,560 observations against actual pinned inout0.2.2/hybrid-array0.4.13, checking equal/disjoint input/output, read-before-write, zero-default4×16, index0 and untouched suffix, and full owner writeback. These tests support the trusted content boundary; they are not a mechanized proof of those crate internals. Existing256 pinned Rust ciphertext comparisons from3c96979 remain separate cryptographic interoperability evidence.

This is backend-independent functional/circuit/compiler refinement. It does not depend on Shamir/EMP representations or modify a protocol security profile.

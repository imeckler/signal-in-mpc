# Key source and sticky rejection components

`TerminalKey` composes the established actual Core terminal value with actual
Prost key validation and the grounded generated schema driver's key adapter.
It retains InvalidKey/InvalidWireType/InvalidTag precedence, constructor, suffix,
and value correspondence without a successful-key or response-validity premise.
The next field-schema invariant must relate those native key checks to Core's
common-key/wire/depth guards and derive the dispatcher transition.

`RejectionClosure` proves invalid Core state remains invalid after each byte,
all arbitrary tails, and finish. It composes the prior bad-tenth-prefix invariant
to rejection of a whole wire even if later bytes form a valid-looking envelope.
This is the actual numeric Core fold, not an assumed rejection predicate.

`check_key_closure.py` validates ancestor receipts and records a fresh immutable
two-module combined kernel check. Full schema streaming/private-end induction
and HTTP/correlation/compiler composition are still open. All inherited
content/allocation/std UTF8/static diagnostic push boundaries remain explicit.
